# 墨境之战 (Ink Realm Clash)

东方幻想回合制对战游戏。实时 3D / 立绘战场 + Canvas 技能演出 + ES modules，**无构建步骤**。
双人 / 人机 / 观战，**16 名角色**、3 张战场。战役已暂弃，平衡实验仅在调试模式下开放。

**2026-09-05 · 墨塑新生**：16 名角色成为真正的低多边形模型，带独立武器、关节、衣饰、
待机/出手/倒地动作；三座浮空擂台使用实时光影。拖动旋转、滚轮缩放，点击模型或名字选人。
战斗中可随时切换 3D / 立绘，不重开对局；无法启用 WebGL 时回退立绘。

首页点 **「3D 造物间」** 可近看全部角色、试动作，并导出 GLB 模型（含材质与关节节点，不含动画片段）。
另有四首原创合成主题：序曲《墨起》、灵泉《听泉破阵》、虚空《悬墨》、熔岩《赤烬行》。
战斗曲随回合推进和生命流失加入打击乐与对旋律；造物间可生成试听、下载 WAV。
音乐与音效分别调节，静音会记住，切到后台暂停。现有战斗规则与平衡参数未变。

首页底部选角色，点「带他出战」直接开启普通人机并补齐阵容；「自由配队」进入完整模式选择。
Three.js 0.180.0 已随项目本地打包，浏览器不访问 CDN，许可见 `vendor/three/LICENSE`。

## 运行

日常入口是桌面快捷方式**「墨境之战.lnk」**（指向 `launch-game.vbs`：隐藏窗口拉起
静态服务器，再自动打开浏览器）。

命令行等价物：

```bash
node serve-game.mjs
```

然后访问 <http://localhost:5566/inkfight.html>。这个服务器零依赖，端口被占用时会
直接退出（假定已经在跑），所以重复启动是安全的。

也可以用 `npx serve .` 或 VS Code Live Server。
**必须走 HTTP** —— ES modules 不能从 `file://` 加载。

## 五种模式

| 模式 | 说明 |
|------|------|
| 双人对战 PVP | 同一台电脑两人轮流操作，各控 4 名角色。开局有 **BAN 阶段**（只有 PVP 有） |
| 人机对战 | 玩家手操 4 人，对面交给 AI，四档难度 |
| 战役模式 | 8 关剧情战役。固定主角剑士「墨白」+ 1 名队友，每通一关解锁一名，最终关单挑墨皇 |
| **观战模式** | **两边都交给 AI，各选一档难度，你在旁边看**（详见下面一节） |
| 平衡测试 | 双方全 AI 自动跑多局并统计胜率（命令行版见下面的 `npm run balance`） |

**难度是两层：AI 决策水平 + 属性加成。**

| 难度 | AI 行为 | 属性加成 |
|------|---------|----------|
| 简单 | 决策噪声大，常选错目标，偶尔白抡普攻，不会配合 | 攻击力 ×0.99 |
| 普通 | 按评分选技能和目标，会集火但配合意识只有一半 | 攻击力 ×0.98 |
| 困难 | 整队集火、不重复上增益、队友濒危时顶上去、不浪费回合、会前瞻攒蓝 | 攻击力 ×1.07 |
| 墨皇（隐藏） | 决策同困难，通关战役后解锁 | 攻击力 ×1.08，SP 回复 ×1.1 |

数值以 `combat.js` 的 `DIFFICULTY_MODS` 为准（这张表会过时，那里不会）。
**困难档也带属性加成**：承诺制让 AI 吃了结构性的亏（玩家看得见它的预告、
它却要兑现承诺），用属性补回来是诚实的做法。
战役模式另有一条独立的属性旋钮（每关的 `enemyMod`），不走上面这张表。

### 👁️ 观战模式

两边都交给 AI，各选一档难度，随机分配或自己指定出战角色，然后看完一整局。

**A 方坐在「玩家」的位置上**——它能看见 B 方的行动预告，而 B 方要兑现自己的承诺。
这正是玩家在人机对战里享有的信息优势，所以这里看到的是
**「一个 A 档水平的玩家去打 B 档 AI」**，不是两个 AI 的对等较量。
换句话说，它把 `difficulty-check.mjs` 量的那件事变成了看得见的一局。

战斗中可以 **⏸ 暂停 / ⏭ 单步 / ⏩ 变速**（1× · 2× · 4× · 0.5×），
快捷键 `空格` 暂停或继续、`→` 单步。单步的粒度是「一个单位行动完」——
停在那个边界上状态已经结算干净，看到的局面是真的。

进度和设置存在 `localStorage`：`inkfight_campaign`（已通关数）、
`inkfight_campaign_totals`（每关战绩）、`inkfight_muted`（静音）、`inkfight_sim`（最近 10 次平衡测试的结果）。

## 玩法

双方各 4 名角色，**每回合各行动一个单位**——队伍人数不影响行动次数，只影响血池总量。

### 这一作没有骰子

胜负不看运气。**同样的局面，永远给出同样的结果**：

- **敌人下一击是公开的。** 轮到你之前，敌方下一个行动的单位会把它要放的技能、
  打谁、打多少伤害全部亮出来，而且**锁定**——哪怕你的操作让这步棋变臭，它也照做。
  于是你可以抢在它出手前打死它、按预告的伤害量开盾、或者干脆打断它。
- **打断是确定的，不是概率。** 「灵能过载」「束缚箭」只要目标 SP 过半就**必定**打断，
  否则必定打不断。SP 条一直看得见，所以这是判断不是赌博——
  代价是**坐在满蓝上会被打断**，该花就得花。
- **重击是蓄能条，不是抽奖。** 每次攻击攒「锋芒」点，攒满 100 必定重击（伤害 x1.5）并清零重攒。
  单位卡上写着 `锋芒 87/100`，所以你可以**留着大招砸在必定重击的那一刀上**。
  多段技能的每一段都单独攒锋芒，所以它们充得特别快。
- **闪避不再让攻击落空**，改成恒定减伤（期望伤害一样，但没有「这下闪没闪掉」）。
  刺客的「消失」仍然是完全免疫——那是主动技能，本来就是确定的。

### 每回合两个决策

- **派谁上。** 每回合你自己挑存活队友里谁出手，**没出手的队友会回复 SP**。
  所以一直派最强的那个会把他的蓝耗干，换人是有理由的。
- **放什么。** 看着敌人的预告决定：抢杀、布防、打断，还是换人去接这一下。

其余：**护盾**优先承伤；**嘲讽**强制敌方集火；每个角色有一个**被动**，
在回合开始 / 重击 / 受击等节点自动触发；键盘 `1`~`4` 释放技能，
`ESC` 取消选目标 / 退出战斗；战场效果会影响全场的伤害或 SP 回复。

### 最终 BOSS：墨皇

不是一个属性更高的术士，而是**三个阶段，各考一种能力，而且每个都有解**：

| 阶段 | 触发 | 他做什么 | 你怎么破 |
|---|---|---|---|
| 书写 | 100%~66% | 稳定积累腐化层 | 腐化层是公开的倒计时，净化 / 打断掐掉爆发 |
| 涂改 | 66%~33% | **每回合行动两次** | 信息量翻倍，靠「轮空回蓝」调度好两个人 |
| 重写 | 33%~0% | **每回合抹掉你一个技能** | 逼你换打法（他不会抹你的普攻） |

## 战绩室

打完一局，结果会自动记在这台设备上（首页 → **📜 战绩室**）。三个页签：

- **我的战绩** —— 每一局的双方阵容、逐人伤害/治疗/击杀、MVP、最高单击。
- **生涯** —— 总场次、胜率、连胜、各难度战绩、我用过的角色。
- **好友战绩** —— 朋友发来的战绩，验完签名和数据才收。

### 分享与防伪

没有服务器，分享靠一串文本（单局约 330 个字符，能直接贴进聊天框）：

```
INK1.WzEsIuWiqOeZvSIsIjAwMXUx…….9tKq3nX2mZ
```

复制、存成文件、或者调系统分享面板都行；朋友在「导入好友战绩」里粘进去就能看。

**防伪是两层，各挡一类人，并且在界面上如实写清了边界：**

| 层 | 挡谁 | 怎么挡 |
|---|---|---|
| HMAC-SHA256 签名 | 拿记事本把 230 改成 9999 的人 | 改一个字符签名就对不上 |
| 自洽审计 | 读过源码、能重新签名的人 | 分项之和要等于总计、最高单击不能超过本人总伤害、角色要在花名册里、MVP 由数据现算而不是存在码里——得把整套数编圆 |

**这不是认证。** 密钥就在游戏代码里，本作也没有服务器可以背书。
它能让随手改数字立刻失效，仅此而已——界面上那段说明写的就是这个意思，别把它删了。

## 目录结构

```
inkfight.html        游戏入口
launch-game.vbs      桌面快捷方式（一键启动）
serve-game.mjs       零依赖静态服务器
src/core/            规则引擎、意图系统、全局状态（纯逻辑）
src/ai/              技能评分与难度包装（纯逻辑）
src/data/            角色 / 场景 / 战役关卡配置
src/game/            回合流程编排 + UI 入口
src/view/            渲染、火柴人、场景、特效、音频
tools/               无头模拟器 + 11 个平衡/深度诊断脚本
test/                单元测试（378 条）
docs/                改动史与历次计划文档
```

**`src/core` `src/ai` `src/data` 是纯逻辑，能直接在 Node 里跑**——
所有平衡诊断都靠这一点。`src/game` 和 `src/view` 碰 DOM，只能在浏览器里跑。

## 模块结构

游戏逻辑全部在根目录的 ES modules 里，`inkfight.html` 只剩结构和样式。

| 文件 | 职责 |
|------|------|
| `inkfight.html` | HTML 结构 + CSS |
| `main.js` | 入口：UI 流程、事件监听、`window` 暴露 |
| `data.js` | 场景与角色数据（`SCENES` / `CHARACTERS`） |
| `state.js` | `gameState` 与工具函数 |
| **`combat.js`** | **战斗规则引擎（纯函数）。`battle.js` 和 `sim.js` 唯一的规则真相来源** |
| `battle.js` | 回合流程编排 + DOM 渲染 + 音效特效（规则计算全部委托 `combat.js`） |
| **`ai-scoring.js`** | **技能评分的唯一实现**：把各类技能收益折算成「等效伤害」以便横向比较 |
| `ai.js` | 难度包装：`aiEasy` / `aiNormal` / `aiHard`。纯函数，可在 Node 里跑 |
| `sim.js` | 无头战斗模拟器（平衡测试用），规则来自 `combat.js`，决策直接调 `aiHard` |
| `campaign.js` | 战役数据：8 关阵容 / 剧情 / 场景 / AI 档 / `enemyMod`，主角与队友解锁表 |
| **`record.js`** | **战绩的数据模型 + MVP + 生涯统计 + 自洽审计**（纯函数） |
| `share-code.js` | 分享码的编解码与 HMAC-SHA256 签名（纯函数） |
| `sha256.js` | SHA-256 / HMAC / base64url，浏览器与 Node 共用同一份实现 |
| `records.js` | 战绩室界面：我的战绩 / 生涯 / 好友战绩 / 导入导出 |
| `save.js` | 本地存档的唯一入口（战役进度、教学、出战局数、战绩、好友） |
| `render.js` | 战斗画面渲染与单位动画 |
| `stickman.js` | 火柴人与武器的 Canvas 绘图（纯绘图，无副作用） |
| `vfx.js` | 技能特效、飘字、粒子 |
| `scene.js` | 场景背景、菜单粒子、场景预览 |
| `audio.js` | BGM 与音效（Web Audio 合成，无音频文件） |
| `serve-game.mjs` | 零依赖静态服务器 |
| `launch-game.vbs` | 桌面快捷方式的启动脚本（**必须保持纯 ASCII**） |
| `test/` | 单元测试，`node --test` 跑 |

## 开发者命令

```bash
npm test                          # 单元测试（Node 内置 node --test，无外部依赖）
npm run balance                   # 无头模拟 4000 局，输出各角色胜率 + 采样均匀度
npm run balance 10000             # 指定局数
node tools/difficulty-check.mjs 6000    # 难度公平性：玩家打各档 AI 的胜率
node tools/campaign-check.mjs 3000      # 战役难度曲线：玩家打 8 关各自的胜率
node tools/campaign-tune.mjs 600        # 战役校准器：逐关扫 enemyMod，直接给出「该填什么」

node tools/depth-check.mjs 2000         # 策略深度：打得好到底值多少胜率
node tools/choice-check.mjs 1500        # 决策存在性：完美玩家的技能使用分布
node tools/skill-audit.mjs 500          # 技能承重：逐个禁掉技能，看主人胜率掉多少
node tools/intent-value-check.mjs 1500  # 对照实验：意图公开值多少策略价值
node tools/stun-check.mjs 3000          # 打断机制值多少胜率
```

判读这几个数字有坑（先手优势、`npm run balance` 只能发现离群角色、
两个深度指标各自都能被钻空子等等），动手改数值前先看 `CLAUDE.md` 的「工作约定」一节。
