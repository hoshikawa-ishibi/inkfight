## 结论先行：升级生成器，不要引入美术资源

三块内容现在**全部是程序化生成**的：

| | 现状 | 在哪 |
|---|---|---|
| 角色 | canvas 画线条火柴人 | `src/view/stickman.js` |
| 场景 | canvas 画渐变 + 波形 + 粒子 | `src/view/scene.js` |
| 音乐 | WebAudio 实时合成 | `src/view/audio.js` |

**这是个很好的起点，别丢掉它。** 换成贴图/音频文件的代价：

- 16 个角色 × 4 种姿态 × 风格统一 = 64 张图，而且**加第 17 个角色就要再画一套**；
  程序化生成时新角色的美术是**免费**的（从它已有的 `color` / `weapon` / `role` 推出来）。
- 会破坏这个项目「零运行时依赖、无构建步骤」的性质——那是它现在最省心的地方。
- 音频文件动辄几 MB，而现在整个游戏没有一个二进制资源。

**「火柴人」和「好看」之间差的不是画工，是四件纯代码的事**：
轮廓的重量感、明暗层次、次级动作、接地感。这四件都能自动化。

## Phase 1 — 角色（收益最大，先做这个）

### 现在为什么显得简陋

1. **所有线条都是 2.5px 等宽** → 没有轮廓、没有重量感。真人画角色第一件事是
   「粗的地方粗、细的地方细」。
2. **单色平涂** → 没有体积。
3. **披风只是一条 sin 曲线** → 动作是「整体一起动」，没有跟随感。
4. **地面阴影是固定椭圆** → 人物像浮在空中。

### 怎么改（全部从已有数据自动推导）

| 做法 | 为什么有效 | 数据来源 |
|---|---|---|
| **锥形肢体** —— 关节处宽、末端细的填充形状，不再用等宽线 | 一次性解决「没有重量感」 | 骨架坐标 |
| **三色调色板** —— 从 `unit.color` 用 HSL 推出 亮/本/暗/轮廓光 四阶 | 每个角色自动获得一致的明暗，不用手配 | `unit.color` |
| **轮廓光** —— 受光侧描一道更亮的边 | 把角色从背景里「拔」出来，这是最廉价的高级感 | 调色板 |
| **次级动作** —— 披风/头发用 3 段链条，跟随身体但滞后 | **让角色显得活着**，比任何静态细节都管用 | 上一帧位置 |
| **挤压拉伸** —— 出手时纵向拉、受击时横向压 | 打击感 | `state` |
| **接地阴影** —— 随姿态和高度变形、变淡 | 人物落到地面上 | 骨架坐标 |
| **武器拖尾** —— 挥击时残留一道渐隐弧线 | 动作可读性 | `state` + 武器类型 |

**关键点：这些全都不需要你画任何东西。** 新角色只要在 `data.js` 里填一个颜色
和武器名，上面七条自动生效。

## Phase 2 — 场景背景

### 现在为什么显得简陋

背景是「一层渐变 + 一条正弦地平线 + 飘粒子」，三个场景结构一样只是换色。

### 怎么改

| 做法 | 为什么有效 |
|---|---|
| **多层视差** —— 远山/中景/近景各按不同速度漂移 | 一下就有了纵深 |
| **程序化远山** —— 中点位移算法生成山脊，每个场景生成一次后缓存 | 每次进同一场景山形一致，但三个场景各不相同，零素材 |
| **带景深的氛围粒子** —— 远的小而暗而慢，近的大而亮而快 | 空间感 |
| **暗角 + 色调映射** —— 四周压暗，整体色调偏向场景主色 | **电影感的廉价来源**，一行 CSS/一次 fillRect 就能拿到 |
| **战斗反馈** —— 大伤害时背景闪一下、地平线抖一下 | 把背景变成战斗的一部分而不是墙纸 |

## Phase 3 — 音乐

### 现在为什么单调

每个场景一段**固定 8 音循环**，`mel:[220,247,262,294,330,294,262,247]`，
听十秒就听遍了。

### 怎么改：算法作曲

| 做法 | 为什么有效 |
|---|---|
| **五声音阶（宫商角徵羽）** | 五声音阶怎么走都不会难听——这是它最适合自动生成的原因，而且贴「墨境」的东方设定 |
| **和弦进行驱动** —— 每 8 拍换一个和弦，旋律只从当前和弦音里挑 | 有了「进行」就有了段落感，不再是原地打转 |
| **带休止的加权随机游走** —— 旋律倾向于走小音程，偶尔跳进，随机插入休止 | **永不重复**，但始终连贯 |
| **战况自适应** —— 总血量越低，节奏越快、声部越密；有人濒死时切紧张模式 | 音乐变成战斗信息的一部分 |
| **古筝式音色** —— 极快衰减的三角波 + 轻微失谐叠加 | 拨弦感，贴设定，两行代码 |

## 备选方案：AI 生成贴图（**不推荐作为主线**）

用户提到不发布、没有版权顾虑，所以这条路是开着的。但要知道代价：

- 16 个角色要风格统一，实际得反复重试；
- 加新角色的成本从「填一行数据」变成「再生成一套图并对齐风格」；
- 需要引入资源目录和加载逻辑，破坏零依赖/无构建。

**建议**：先做完 Phase 1~3。如果之后仍想要贴图，那时的程序化渲染已经定义了
每个角色的姿态和配色，正好可以拿它当生成贴图的参考图——顺序反过来会更省力。
