# 战斗小人美术升级计划

> 2026-08-30 方案获确认后已按数据驱动路线接入 16 人；新增角色按 `CHARACTER_WORKFLOW.md`。
> 战役模式继续搁置；本计划只处理通用选角界面和战斗中的 16 名角色。

## 结论

推荐采用 **数据驱动的程序化小人 2.0**，AI 只用于前期概念探索，不直接生产多动作精灵图。

```text
AI 概念试片（找轮廓和服装语言，不进游戏）
  → 共用程序化骨架与绘制部件
  → 每名角色一份 visual 配方
  → 少量角色专属动作 / 拖尾
  → 同一套素材服务选角预览与战斗
```

这不是最“华丽”的路线，但最适合本项目：角色很多、显示尺寸很小、没有构建步骤，而且
以后还可能继续加角色。它能把新增角色的成本控制在“一条配置 + 必要时一个新部件”，不会
变成每加一人就画 idle / attack / hurt / stun / dead 五套贴图。

## 为什么不直接做 AI 精灵图

当前实际尺寸：

- 战斗：`100×92` Canvas。
- 选角与禁用预览：`80×90` Canvas。
- 一屏同时显示 8 人，角色还要让位给姓名、数值、血条和意图。

AI 很容易画出一张漂亮立绘，但在以下方面成本会迅速膨胀：

- 16 人必须保持同一比例、描边、光源和视角。
- 每人至少 5 种状态，左右阵营还需要可靠镜像。
- 动作帧之间必须保持脸、服装、武器和身体长度一致。
- 细节缩到约 90 像素后大多消失，投入与实际收益不成比例。
- 后续修改武器或新增角色会重新触发整套一致性工作。

因此 AI 的合理角色是：生成概念板帮助选择轮廓、服装层次和材质；最终战斗资产仍由可控的
Canvas 部件组合完成。未来若要做大尺寸角色图，可以另立“选人肖像”项目，不与战斗小人绑死。

## 目标：一秒认出是谁

验收重点不是放大截图是否精致，而是在真实尺寸下能不能认人。辨识度按以下优先级建立：

1. **外轮廓**：头部、肩宽、下摆、背部附件、武器长度。
2. **静态姿态**：重心高低、身体朝向、持武器方式。
3. **主动态**：披风、长发、符纸、烟、火、灵流等一个角色只占一种。
4. **攻击节奏**：突进、蓄力、旋转、后撤或远程释放。
5. **颜色与小细节**：只能辅助辨认，不能承担主要身份。

把所有角色临时显示成同一种灰色时，如果仍能区分大部分人，才算轮廓设计成功。

## 统一美术语言

新场景已经确定“现代水墨 + 矿物色 + 清晰大形”。小人应采用同一世界语言：

- 身体是墨块和粗细变化明确的笔势，不是塑料 3D，也不是等宽火柴线。
- 主色只占一块，暗部统一偏墨色，轮廓光用场景对应的冷/暖矿物色。
- 每人最多一个高辨识附件、一个次级动态，避免 90 像素里堆装饰。
- 武器保持夸张比例；小尺寸下，武器比五官更能说明职业。
- 脸只保留眼神和极少表情，不尝试画鼻嘴和复杂头发纹理。
- P2 继续可靠镜像；文字、阵营与状态颜色不画进角色本体。

## 技术结构

### 1. 视觉配置和战斗配置分离

建议新增 `src/data/character-visuals.js`，按角色 id 保存纯表现数据，避免把 `data.js` 的战斗
数值继续撑大：

```js
export const CHARACTER_VISUALS = {
  swordsman: {
    body:'balanced', stance:'forward', head:'headband', outer:'shortScarf',
    weapon:'sword', accent:'edgeLight', motion:'scarf', attack:'dashCut'
  }
};
```

字段只选择有限的共用部件。新角色优先组合现有部件；只有轮廓确实无法区分时才新增一种。

### 2. 共用骨架，不复制 16 份绘制函数

渲染管线保持一条：

```text
pose(state, time, stance)
  → body profile
  → far-side equipment
  → torso / limbs / head
  → near-side equipment
  → character accent
  → weapon trail / state feedback
```

`idle / attack / hurt / stun / dead` 仍使用同一份状态接口。角色差异来自配置和部件，不允许
出现 `if (unit.id === ...)` 散落在主绘制流程里。

### 3. 部件库保持小而有复用

首轮上限：

- 体型 4 种：轻、均衡、重、长袍。
- 站姿 5 种：前压、后撤、沉腰、直立施法、悬浮。
- 头部附件约 8 种。
- 外轮廓附件约 10 种。
- 攻击节奏 6 种：直劈、突进、旋转、重砸、射击、施法。

16 人不是 16 套独立代码，而是这些部件的受控组合。

而不是继续往上添加细节。

## AI 概念试片怎么用

不一次生成 16 张。首轮只选四个轮廓差异最大的代表：

- 守卫：测试重型宽轮廓。
- 法师：测试长袍与施法轮廓。
- 刺客：测试轻型前倾轮廓。
- 鼓姬：测试大型圆形附件。

生成一张“四人灰阶剪影概念板”，要求同视角、同头身比、无文字、无背景；只比较轮廓，
不把生成图直接裁成游戏素材。确定方向后，再由程序化试片复现这四人。

如果 AI 概念很好看但无法被部件库复现，优先简化概念，而不是改走整套 AI 精灵图。

## 验收清单

- 灰阶截图中，至少 12/16 人无需姓名即可辨认；四组易混角色必须能两两区分。
- 三张场景下都可读，不能只在黑底上好看。
- 角色主色改成相近颜色后，轮廓仍承担主要辨识度。
- `80×90` 和 `100×92` 都没有细线闪烁、附件糊成一团或武器被裁切。
- P2 镜像、受击、眩晕、死亡、选择预览全部走同一套视觉配置。
- 新增角色有文档化步骤和默认回退，不需要复制一份角色渲染器。
- 小人升级不修改战斗规则、AI评分或角色数值。
