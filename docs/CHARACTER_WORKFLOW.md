# 新增角色美术工作流

这套流程用于给新角色增加战斗小人。角色美术和战斗数值分离：数值仍在 `data.js`，视觉配方
统一放在 `character-visuals.js`，正式绘制只有 `stickman.js` 一条链路。

## 先写视觉身份证

新增角色前先回答六项：

1. `body`：轻、均衡、重、运动型、长袍、宽袍或高瘦。
2. `stance`：前压、直立、低重心、蹲伏、后撤、悬浮、拔刀、展开或侧身。
3. `head`：一个在 90 像素下仍看得见的头部轮廓。
4. `outer`：一个主附件，例如盾、箭袋、葫芦或背包。
5. `attack`：最接近的攻击节奏。
6. `accent`：角色的特效语义；不能只写颜色。

至少要让新角色和现有角色在上述六项中有两项明显不同。不要用“同一小人换颜色”占位。

## 接入步骤

1. 在 `src/data/character-visuals.js` 增加与角色 id 同名的配置。
2. 优先复用现有体型、站姿和部件。
3. 确实缺少轮廓时，在 `stickman.js` 对应的小型部件函数中新增一个 `case`；不要在
   `drawStickman()` 主流程中写角色 id 判断。
4. 武器沿用角色数据的 `weapon` 字段；若出现新武器，只扩充 `drawWeapon()`。
5. 打开 `tools/character-art-preview.html`，依次检查：
   - 三张场景；
   - 待机、攻击、受击、眩晕、死亡；
   - `100×92` 战斗尺寸与 `80×90` 选角尺寸；
   - P2 镜像方向。
6. 进入正式选角页和真实战斗再检查一次，预览页不能代替最终验收。
7. 运行 `npm test`。自动检查会阻止漏配、冗余配置和完全重复配方。

## 修改现有角色

调整顺序：轮廓附件 → 站姿 → 体型 → 攻击节奏 → 颜色。小尺寸下先加细节通常没有效果。
若附件被裁切，优先收紧动作位移，不要把身份附件整体缩小。

## 角色档案与未来立绘

首页的角色档案由 `src/view/character-gallery.js` 统一生成，属性、定位、被动和技能都直接读取
`data.js`，战斗形态直接调用 `drawStickman()`。不要为档案页再维护一份角色文案或小人配置。

立绘舞台已经用 `data-portrait-for="角色id"` 标出稳定挂载点。正式立绘放进 `assets/portraits/`，
然后只在 `src/data/character-portraits.js` 增加 `角色id → 透明 PNG/WebP 路径`。档案模块会统一生成
图片；不要把图片地址、裁切参数和角色判断散落在 HTML/CSS 中。没有立绘的角色继续显示预留状态，
因此可以逐个替换。测试会检查映射中的角色和文件是否真实存在。

## 不该做的事

- 不在 `battle.js` 写美术分支。
- 不把视觉字段塞进战斗单位状态或模拟器。
- 不为一个角色复制整份渲染函数。
- 不直接把 AI 生成的多动作图塞进游戏；AI 可以做概念参考，但最终资产必须适配共用系统。
- 不只在纯黑底或放大截图下验收。
