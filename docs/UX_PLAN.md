# UX_PLAN.md — 玩家看不懂什么，以及怎么修

> **状态：未开工。** 本文件是 2026-08-30 玩家体验实测之后定下的方案，
> 分 5 个阶段，每个阶段可独立完成、独立验收。
> 上下文被 clear 之后，从这份文件继续即可。

## 这份计划从哪来

2026-08-30 用一个「第一次玩这个游戏的普通人」人设的 agent 做了实测
（工具只有浏览器，读不到源码，全靠界面判断）。它逛了角色档案和玩法说明、
看了一场观战、打了两局人机（简单 + 困难）。

**核心结论：这个游戏的机制大多是好的，但玩家看不见。**
实测里几乎每一条困惑，背后的机制查下来都是**设计得对、注释里想得清楚、
测试也锁住了**，唯独没告诉玩家。所以本轮的方向不是改战斗，是改呈现。

## 总原则（本轮）

- **不改战斗规则。** `combat.js` / `ai-scoring.js` / `ai.js` / `intent.js` 一律不动。
  所有改动落在 `game` / `view` 层和 `data.js` 的文案字段。
- 因此本轮**不需要跑** `balance` / `depth-check` / `difficulty-check`。
  只需要 `npm test`（`syntax.test.js` 会把全仓库 `node --check` 一遍）+ 浏览器实测。
- **战役已从「暂缓」升级为「暂弃」**，墨皇难度和平衡测试一并藏起来。
  见阶段 0，以及 `CLAUDE.md` 的工作约定。

## 阶段 0 — 把没做完的东西藏起来

玩家目前能看到三样还不该给他看的东西：战役（暂弃）、墨皇难度（依赖战役解锁）、
平衡测试（**会把胜率直接摊给玩家看**）。

**做法：三样全部改成「调试模式开启才出现」。**

调试模式已经存在（顶栏 🔊 连点 5 次，`main.js` 的 `isDebug()`），
本来就是「一处撒谎即全解锁」的设计。这里把它的语义从
「跳过解锁门槛」扩成 **「实验功能总开关」**，概念反而更干净。

| 改哪 | 怎么改 |
|---|---|
| `inkfight.html:429` 模式卡 | 标题 `战役模式` → **`战役（暂弃）`**；整张卡 `display:none`，`isDebug()` 时才显示 |
| `inkfight.html:437` 模式卡 | `平衡测试` 整张卡同样藏起来 |
| `main.js:111` 难度屏 | 墨皇的显示条件从 `getCampaignProgress() >= 总关数` 改成 **`isDebug()`** |
| `main.js` `initSpectateScreen` | 观战里的墨皇档同上，两处规矩必须一致 |
| `main.js` 调试模式弹窗文案 | 加一行醒目警告：**「以下是未完成的测试中功能，随时可能不可用或不平衡」** |

**注意**：墨皇现在的门槛是「通关战役」。战役一旦藏起来就没人能合法通关，
墨皇会自然变成调试专属——但**已有存档里 `inkfight_campaign` 已经是 8 的人仍然看得到**，
所以必须显式改成 `isDebug()`，不能指望它自然消失。

**验收**：全新浏览器配置下，标题 → 开始对战，只应看到「双人对战 / 人机对战 / 观战」
三张卡；人机难度只有简单/普通/困难三档。连点 5 次 🛠 之后三样都出现，且弹窗写明是测试中功能。

## 阶段 1 — 把「暴击」改名成「锋芒」

### 为什么要改名

这个游戏的暴击**不是掷骰子**（`combat.js:326`）：

```
critMeter += (技能暴击 + 角色暴击)      // 每打一下攒
if (critMeter >= 100) { 伤害 x1.5; critMeter -= 100 }   // 攒满必定触发，清零重攒
```

也就是「暴击率 12%」的真实含义是**每击 +12 点，攒满 100 必爆**，
每 9 下必爆一次，而且玩家可以数出来是哪一下。闪避也是同样思路
（`combat.js:335`，概率闪避已经被改成确定性减伤，注释写着
「5~10% 的闪避率本来也构不成任何决策，只贡献噪声」）。

**这是一整套刻意去掉随机性的设计，但「暴击率 %」这个名字把玩家的心智模型
拽回了「概率」，于是没人去看那个蓄能条。** 实测里 agent 从头到尾没提过
`★ 47/100` 一次——它看见了，但因为以为暴击是概率，那个数字就变成了背景噪声。

**不改成随机。** 拳师整个角色（多段 → 快速充能 → 频繁触发 → 被动「寸劲」回蓝）
和刀娘的「蓄刃」都建立在充能制上，改随机等于把两个角色的机制废掉。

### 改什么

**只改 UI 文案，代码里的 `crit` 字段名不动。**

| 现在 | 改成 |
|---|---|
| 暴击率 12% | **锋芒 +12 / 每击** |
| `★ 47/100`（`render.js:135`） | **锋芒 47/100**，tooltip：攒满 100，下一击必定重击 |
| `💥54伤害`（`battle.js:541`） | **`💥54 必定重击`** |
| 玩法说明「暴击 x1.5 伤害」 | 「**锋芒**攒满 100 触发**重击**（伤害 x1.5）然后清零重攒——这是确定的，不是概率」 |
| 战斗日志「💥 暴击！」 | 「💥 重击！」 |

术语固定为两个：**锋芒**（蓄能条）/ **重击**（触发的那一下）。
备选名「墨锋」，如果觉得墨味更该重一点可以换，但两处必须同时换。

**要 grep 干净所有出现「暴击」的地方**：`data.js` 的技能描述、角色档案、
玩法说明、战斗日志、tooltip、`render.js` 的属性行。漏一处就等于两套术语并存。

### 多段技能

实测里 agent 把「两段各 8 点」误读成了 bug。但**人类玩家不会盯着小数字算**，
所以**不做飘字改造**，只在文字里把因果说清楚：

- 技能描述补一句：多段技能的**每一段都单独攒锋芒**，所以充能特别快
- 拳师的角色页要点出那个循环（放到阶段 4 的机制解读里）

## 阶段 2 — 状态图标必须自己说清楚自己

实测里 agent 把 `💫扰乱` 和 `🚫免疫2` 读成了**一个**叫「扰乱免疫」的状态。
这不怪它：这两个图标是**因果关系，永远同时出现**（刚被打断的那一刻必然同时挂上），
挨着显示就长得像一个复合状态。

| 改哪 | 怎么改 |
|---|---|
| `render.js:53` | 标签 `免疫2` → **`打断免疫2`**。光写「免疫」说不出免疫的是什么 |
| `render.js:52` | `💫` 目前同时给「扰乱」和「打断」两个状态用（后者是旧版对照状态），换掉其中一个图标 |
| 状态条布局 | 「扰乱」和「打断免疫」要么合并成一条（「被打断：本次行动 60% 威力，2 回合内免疫」），要么明显分开，不能继续贴着 |

三个状态的完整因果（写进阶段 3 的词典）：

1. **前提**：SP 攒到上限 50% 才可能被打断（`combat.js:394`）——SP 越满越危险，
   这就是标题界面那句「小心灵能过载」
2. **命中**：挂 `扰乱`，下一次行动伤害/治疗压到 60%（不是跳过回合），行动完自动解除
3. **副作用**：同时获得 `打断免疫 2`，接下来自己的 2 个回合内不会再被打断
   （存在理由是防连锁——没有它两个打断角色能把对方锁死）

## 阶段 3 — 一次性教学提示 + 常驻机制词典

### 为什么不做新手引导关

贵，而且和战役暂弃撞车。

### 为什么不能只靠玩法说明

**静态文本已经被证伪了。** 实测里 agent **读过**玩法说明，扰乱那条甚至原样复述了出来，
然后照样不懂——因为读的时候没有上下文，读完就忘。

### 3a. 一次性提示（学习发生在困惑发生的那一刻）

某个机制第一次落到玩家身上时，弹一条一次性说明。存 `localStorage`
（新 key `inkfight_taught`，存一个已教过的条目集合，和 `inkfight_muted` 同样的路子），
每条只弹一次。

| 触发时机 | 说什么 |
|---|---|
| 第一次有技能显示 💥 | 锋芒攒满了，这一击**必定**重击——不是运气，是数出来的 |
| 第一次被打断 | 你 SP 过半被抓了；这次行动只有 60% 威力，但接下来 2 个回合不会再被打断 |
| 第一次用多段技能 | 每一段都单独攒锋芒，所以它充能特别快 |
| 第一次轮空回蓝 | 这回合没派上场的队友会回蓝——不是所有人都该一直出战 |
| 第一次看到墨蚀 | 第 18 回合起每回合掉血且越掉越多，无视防御和护盾，逼局面收尾 |

### 3b. 常驻机制词典（打到一半忘了可以查）

一个随时能打开的词条窗口，内容就是上面这些说明的常驻版。

- **入口两个**：标题界面的「玩法说明」里放一个入口；**战斗界面放一个小 ❓ 按钮**
  （用户明确要的是「打到一半忘记了可以看」，所以战斗内入口是必须的）
- **词条**：锋芒 / 重击、灵能与扰乱、打断免疫、护盾、嘲讽、多段技能、
  墨蚀、轮空回蓝、场景效果、行动经济（每回合各出手一人，人数只影响血池不影响出手次数）
- 战斗中打开时**不能推进回合、不能触发 AI**，关掉回到原状态

### 3c. 玩法说明里有一条是错的，顺手修掉

`main.js:56` 现在写着「**嘲讽**强制集火」。在承诺制下，嘲讽**拦不住已经预告出去的那一击**
（`intent.js:92` 只在目标已死时才重解目标）。实测里 agent 就是信了这句话去救牧师，
结果牧师照样被打死。

本轮不改嘲讽的行为（见「本轮不做」），所以**改文案**：
「嘲讽：让敌人**之后的决策**优先打你——但敌人已经预告出来的那一击不会改道」。

## 阶段 4 — 角色档案里的「机制解读」（带解锁门槛）

### 问题

好几个角色是有巧思的，但**光看「定位」两个字看不出来**。
拳师写着「多段连击」，实际是「多段 → 快充锋芒 → 频繁重击 → 寸劲回蓝」的一整个循环；
刀娘的「蓄刃」是「这回合不打人，换下回合一个确定的重击」，是个真决策。
这些现在全埋在数值里。

### 做法

角色档案页在现有的属性 / 被动 / 技能之下，加一段 **「机制解读」**：
用两三句话讲清楚这个角色**靠什么循环赢**、**什么时候该派他上**。
文案写在 `data.js` 的角色字段里（比如 `insight`），呈现在档案页。

### 解锁门槛

**不要一开始就全给**——16 段解读一次性摊开，玩家一段都不会看。

**推荐规则：用这个角色出战满 3 局解锁他自己的机制解读**（输赢都算）。

- **为什么按角色而不是按难度**：解读讲的是这个角色，门槛就该挂在这个角色上。
  「打过普通 3 次解锁全部」会在玩家还没碰过那个角色时就把解读给他，还是不会看。
- **为什么不要求赢**：要求赢会把门槛压在**最难用的角色**头上——而那恰恰是
  最需要解读的角色，正好反了。
- **调试模式下全部解锁**（和其它门槛一致）。

### 存档

需要一个新 key `inkfight_charplays`，存 `{角色id: 出战局数}`。

> **这不违反 CLAUDE.md 那条「解锁门槛不要各存一份进度」。**
> 那条规矩针对的是**同一份知识存两份**（墨皇难度 / 战役关卡 / 队友全都从
> `inkfight_campaign` 推，就是因为它们本质上是同一件事）。
> 「每个角色出战过几局」是一份**全新的知识**，从现有存档里推不出来，
> 所以它需要自己的 key。**但也只能有这一个 key**——别再为「解读是否已读」
> 之类的东西另开第三个。

## 本轮不做（有明确理由，别顺手做了）

- **不改嘲讽的行为。** 让嘲讽能改写已承诺的目标，会直接改变战役第 8 关的难度
  （那关是校到 42% 的），而战役已暂弃。等战役解冻再说。
- **不收窄意图预告。** 原打算「预告只在墨皇和 BOSS 战保留」——墨皇和战役都藏起来了，
  这条现在没有落点。**注意第 8 关的 `difficulty` 字段是 `'hard'` 不是 `'nightmare'`**，
  以后真要按难度档 gate 预告时，这个坑会咬人。
- **不动 `focusFoe` / `teamwork`。** AI 整队集火确实让玩家操作空间变小，
  但打散它等于用降低难度换趣味，代价会出现在 `difficulty-check` 上。
  而且集火最凶的墨皇档已经藏起来了，困难档的压力可以接受。
- **不给别的角色加嘲讽。** 全 16 人只有守卫有嘲讽，「反集火必须带守卫」是个真问题，
  但扩散嘲讽要动 `ROSTER_PLAN.md` 那套「每个角色占一个独立机制位」的原则，
  属于角色设计决策，不在本轮范围。
- **不做多段技能的飘字改造。** 人类玩家不会盯着小数字算，文字解释就够。
- **「似乎有些犹豫」不管。** 实测里 agent 没看懂这条日志，但那是 agent 的误判
  （它把它和多段伤害绑成了一件事），人类玩家不会去追究这行字。

## 验收

每个阶段独立验收，做完一个提一个。

- **每阶段**：`npm test`（`syntax.test.js` 会 `node --check` 全仓库并核对 import 目标）
- **阶段 0 / 2 / 3 / 4 还要浏览器实测**——这几阶段改的都是看得见的东西，
  测试断言不了「玩家能不能看懂」
- **浏览器实测必须静音**：先 `localStorage.setItem('inkfight_muted','1')` 再刷新，
  然后才开始点击（任何一次点击都会触发 `Audio.init()`）。**测完关标签页**，
  只 `preview_stop` 不够，页面还在跑
- 本轮**不需要**跑 `balance` / `depth-check` / `difficulty-check` / `campaign-check`
  ——没有改战斗规则

## 顺序建议

0 → 1 → 2 → 3 → 4。

阶段 0 最该先做（藏掉不该给玩家看的东西，成本最低）。
阶段 1 和 2 是纯文案 + 标签，改完游戏立刻好懂一大截。
阶段 3 是本轮工作量最大的一块（要新建提示系统和词典窗口）。
阶段 4 依赖阶段 1 的术语已经统一，所以放最后。
