# 角色扩充 · 计划（8 → 16）

> 起因：用户反馈「策略性不够主要就是因为两侧人不够多，而且只有 8 个角色，
> 职业看上去太单调」。

## 为什么扩池子能同时解决两件事

1. **单调**：8 个全是经典 RPG 职业（剑士/法师/牧师…），机制空位很多没人占。
2. **人数上不去**：实测 4v4 反而比 3v3 差（策略价值 50.3 vs 61.0），
   根因是**只有 8 个角色，双方各 4 人等于每局用光全部角色，阵容失去变化**。
   池子翻倍之后 4v4 才谈得上。

对局种类：3v3 从 `C(8,3)² = 3136` 涨到 `C(16,3)² = 313600`。

## 设计原则

**不做换皮。** 每个新角色必须占一个现有 8 人**没占的机制空位**——
这是本项目反复验证过的结论：深度来自「选项多且互相有差异」，
光加数量不加差异等于没加。

现有 8 人占掉的位置：

| 角色 | 机制身份 |
|---|---|
| 剑士 | 破防 combo + 均衡输出 |
| 法师 | 高倍率爆发 + 打断 |
| 守卫 | 护盾 + 嘲讽 + 反弹 |
| 刺客 | 中毒 + 主动闪避 + 处决 |
| 牧师 | 单体治疗 + 净化 + 单体增益 |
| 狂战士 | 越残越强 + 吸血 + 不屈 |
| 弓手 | AoE + 打断 + 暴击叠层 |
| 术士 | 腐化叠层 + 一次性爆发 |

**空着的位置**（新 8 人各占一个）：

| 新角色 | 机制空位 | 为什么之前没有 |
|---|---|---|
| 刀娘·绯樱 | **暴击蓄能操控** | 蓄能条是新机制，还没人围绕它做文章 |
| 阴阳师·白狐 | **群体减防** | 减防只有剑士单体带一手 |
| 机关师·墨匣 | **群体护盾** | 护盾只有守卫给自己 |
| 鼓姬·雷鸣 | **群体增益** | 增益只有牧师单体 |
| 医仙·青囊 | **群体治疗** | 治疗只有牧师单体 |
| 影武者·无面 | **高闪避 + 受击反击** | 反弹只有守卫，且很弱 |
| 拳师·铁膝 | **多段连击** | 全场没有一个多段技能 |
| 炼墨师·陶朱 | **资源转换（HP↔SP）** | 只有剑士「剑气」一手，没人以此为核心 |

## 需要新增的机制（**3 个类型 + 2 个字段**）

刻意压到最少——每加一个都是 `data.js` / `combat.js` / `sim.js` / `battle.js` /
`ai-scoring.js` 五处同步点，而「同一份知识多份实现」是本项目的头号病因。

| 新增 | 说明 |
|---|---|
| `healAll` | 群体治疗（对称于已有的 `damageAll`） |
| `shieldAll` | 群体护盾 |
| `buffAll` | 群体增益 |
| `hits` 字段 | 伤害技能打 N 段。**每段各自结算**，所以各自给暴击蓄能条充能 |
| `critCharge` 字段 | 直接给自己的暴击蓄能条充值，用来「攒满下一刀」 |

`hits` 和 `critCharge` 是刀娘/拳师的核心，也是唯二和**暴击蓄能条**联动的设计——
那个机制现在只有被动地攒，没人主动玩它。

## 步骤

- [x] 1. `combat.js`：`hits` / `critCharge` 的规则，`healAll`/`shieldAll`/`buffAll` 的执行
- [x] 2. `sim.js` + `battle.js`：三个新类型接进 switch（**漏一个不会报错，只会静默什么都不做**，
      `test/skill-coverage.test.js` 就是为这个写的）
- [x] 3. `ai-scoring.js`：三个新类型的评分 + `hits`/`critCharge` 计入伤害估算
- [x] 4. `data.js`：8 个新角色
- [x] 5. `stickman.js`：8 种新武器画法
- [x] 6. 平衡：`npm run balance` + `pair-check` 找外群
- [x] 7. 复查人数：池子翻倍后重扫 3v3 / 4v4 / 5v5
- [x] 8. 战役不受影响（它用固定阵容，新角色不进战役）


---

## 结果（2026-08-29）

**16 个角色、每方 4 人，全员胜率在 ±5 以内，零外群，差距 9.0**——
这是本项目历史上最好的平衡状态（起点是 8 人时代的 40.5）。

| 指标 | 8人3v3 | **16人4v4** |
|---|---|---|
| 角色胜率差距 | 8.4 | **9.0**（人数翻倍还能守住） |
| 策略价值 | 55.2 | **56.9** |
| 对局种类 | 3136 | **3312400** |
| 难度四档（一般玩家） | 81.4/64.2/52.4/38.2 | **86.0/61.7/47.9/34.7** |

目标曲线 85/65/50/35，四档全部落在 ±3.3 内且单调。

### 人数上限解开了

8 个角色时 4v4 会塌（策略价值 61.0 → 50.3），因为双方各 4 人就用光了全部角色。
16 个之后重扫：2v2 54.7 ／ 3v3 52.4 ／ 4v4 53.3 ／ 5v5 53.6 —— **不再塌**。
选 4v4 是因为用户明确想要更多人，而数据显示它不再有代价。

### 两次都踩到的同一件事：改人数会重排 AoE 的强度

AoE 的收益随目标数线性增长。3v3 那次弓手「穿透箭」冲到 69.2%；
4v4 这次弓手/术士/机关师/鼓姬集体到 57~63%。**每次改人数都要专门做一轮 AoE 下调。**

### 布局

4 张卡竖排在任何屏幕都会溢出，所以 `.team-side` 改成会换行的网格
（2 人一列、3~4 人自动两列），卡片宽度收到 225px。实测 4v4 不溢出。

### 测试里又抓到两处写死的平衡数值

- `skill-coverage.test.js` 的「8 个角色 32 个技能」——改成按实际数量断言。
- `ai-teamwork.test.js` 的 `b.hp = 85`（假设法师 92 血）——改成按 maxHp 比例算。

**这已经是第三次了**，规律很清楚：测试里凡是写死角色数量/血量/费用的断言，
都会在下一次调数值时假报错，而且报的还是无关的地方。
